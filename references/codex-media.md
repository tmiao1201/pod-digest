# Codex 图卡与视频执行

## 选择交付范围

- 「digest／总结」：摘要及三素材块。
- 「出卡片／出图卡」：实际图片，以及分镜、逐字文字清单和最终提示词。
- 「一条龙／播客到图卡」：获取或复用逐字稿 → 中文摘要 → 核验 → 图卡 → 看图验收。
- 「只要提示词」或「只要 HTML」：按指定格式交付。
- 「生视频」：按本文视频部分检查当前能力；不因为模型支持多模态就承诺已接通视频生成。

用户已要求图卡且已有内容时，可直接选择合适风格和张数执行。已有指定分镜、张数、风格或仅摘要要求优先，不为每张卡重新确认。未指定数量的一套一般为 3–6 张；安装验证或明确样卡请求可只生成 1 张，并如实标明是样卡。

## 先锁内容与证据

复用已有摘要时，运行原项目 `scripts/verify_digest.py <episode_dir>`，检查实际退出码与提示；逐卡回到相关原稿核对。新写摘要时按主技能通读原稿并完成原有质量门。程序通过不等于事实已获外部证实，也不等于说话人归属、医学或投资结论已验证。

每张卡只表达一个观点或关系。正文尽量不超过 40 个中文字；出处页脚单独计算。正文过密则拆卡。为每卡保存：

- `id`、主题、逐字 `text_manifest`（包括标题、标签、页脚）。
- `source`：节目与集数、原始链接（元数据中有才填）、本地原稿路径、支撑内容片段。
- `timestamp` 及精度：逐句时间或「章节起点」。无逐句时间时不要把章节时间包装成精确引文时间。
- `claim_type`：嘉宾观点／嘉宾引用数据／外部核实事实／编辑解释；简述相关利益关系。

金句必须逐字回对及核对说话人；转述不加原话引号。不能把嘉宾推测画成定律或确定预测。🟢「嘉宾引用数据」不自动升级为「已独立核实」。模型不应自行补品牌、数据、行情或人物身份。

## 分镜与风格

用素材块①作为初稿，必要时简化不可靠的数字、未验证的公司对应关系和含糊归属。

- 有明确风格：直接采用。
- 可用的 `ted-imgstyle` skill 能提供更多风格；需要其风格时读取该 skill 及所选风格文件。用户已要求直接出图时，沿用已给偏好或合理默认，不另起风格审批流程。
- 无偏好：从 [card-styles.md](card-styles.md) 选 G1 手账、G2 扁平信息图、G3 黑白编辑；概念流程默认 G2，商业史可用 G3。

风格参考中「复制提示词给模型」描述的是旧版交付方式；Codex 中应继续执行已请求的生图。同一套统一画幅、色板、字号层级、页脚位置。画幅比例由用户要求或风格决定，提示词可写 3:4；不要凭提示词就声称实际输出尺寸严格匹配，交付前检查真实尺寸。

## 实际调用内置生图

先读当前可用的 `imagegen` skill。使用会话实际提供的 `image_gen` 工具；以当前工具 schema 为准，不固定模型名或编造 `output_path`、尺寸等参数。

生图提示词包含用途、画面结构、统一风格、逐字文字清单、事实约束、来源页脚及需要避免的内容。首次新图不传参考图参数。需要沿用首张卡或编辑本地图片时，先查看图片，再按当前工具文档传参考图；不同时使用两种参考图机制。

通常一张独立图片对应一次调用；请求独立卡片时不把多张拼成一张海报冒充完成。正常内置生图不需要用户另配 API key。工具失败或不可用时如实报告，保留可复用提示词；仅在用户明确选择 API/CLI 路径后才切换。遵守本技能失败次数限制和当前工具的重试规则。

## 文件与视觉验收

默认新增 `<episode_dir>/cards-codex/<run-id>/`，避免覆盖历史图片或摘要。保存：

```text
card-01.png          # 采用实际返回的格式与扩展名；逐张保存
storyboard.md        # 分镜、逐字文案与来源说明
prompts.md           # 实际使用的完整提示词
manifest.json        # 每卡证据、时间精度、生成工具、实际文件和验收状态
```

生成图片先使用工具实际返回的路径；如果只返回图片内容，按该工具支持的方式保存。工具默认目录里的成品复制到本期运行目录，保留原文件。不要假设工具写入了提示词里提及的路径。

逐张查看实际图片，核对中文有没有错字或漏字、关系箭头是否表达正确、引文和数字是否与文案一致、出处是否可读、内容是否出框、尺寸和张数是否满足要求。知识图卡默认使用完整不透明底色，还应检查实际透明度，避免透明背景导致标题或出处在深色界面不可读；用户要求透明素材时按其要求处理。有问题时使用生图编辑功能修正并复看，保留版本；未完成的卡注明原因。不要将未查看的图片标成通过。

最终展示实际图片并链接本期文件和提示词，简要报告使用内置生图及完成张数。已有摘要的来源验证、生成完成、视觉验收是不同结果，分别按证据记录。

## 视频请求

- 用户要求「配音视频／图卡加配音／带字幕短视频」：读取 [narrated-video.md](narrated-video.md)，实际生成旁白、同步字幕与图卡动效 MP4。可复用入口为 `scripts/make_video.py`，其依赖按参考文档检查。
- 用户要求静音图卡动效时：使用实际可用的本地渲染工具制作转场和轻微推拉；按实际输出报告，不要求额外配音。
- 用户指定生成模型的新动态场景时：先查当前可调用的视频生成工具，再按其契约执行。没有对应工具时说明能力缺口，不用幻灯片代替，也不自动安装收费服务。

多模态理解不代表任意音视频工具都已接通。音频转写、声音合成、图卡动效和生成模型视频是不同执行路径；始终报告实际使用的能力和产物。
